# Accessibility

SUI aims for WCAG 2.2 level AA. Part of that is checked automatically in CI. The rest is a keyboard checklist that you run by hand when you change an interactive component.

## What CI checks

The visual regression workflow (`.github/workflows/visual.yaml`, see [visual-testing.md](./visual-testing.md)) also runs an [axe](https://github.com/dequelabs/axe-core) audit with `@axe-core/playwright`:

- **Which stories.** Every story tagged `visual` (including the stress stories), plus every story tagged `a11y`. The `a11y` tag audits a story without taking a screenshot. The keyboard-driven components carry it on their story meta: Tabs, Toggle button group, Slide group, Stepper, Date picker, Autocomplete, Radio, Select, Checkbox and Switch.
- **Where.** Chromium at 1280 px, in the light and the dark theme. The audit does not depend on the browser, so it does not run in WebKit.
- **Which rules.** The WCAG 2.0, 2.1 and 2.2 level A and AA rules (`wcag2a`, `wcag2aa`, `wcag21a`, `wcag21aa`, `wcag22aa`).
- **What fails.** Any `serious` or `critical` finding. `minor` and `moderate` findings, and best-practice rules, show in the Storybook **Accessibility** panel (`@storybook/addon-a11y`) only.

The spec is `tests/visual/storyAccessibility.visual.ts`, and the rule set lives in `tests/visual/constants/a11yAudit.ts`. A failure prints one line per element: the impact, the rule, the element's selector and how to fix it.

To audit a new story, give it the `visual` tag (it is then screenshotted too) or the `a11y` tag:

```ts
export default {
  title: 'UI Components/MyWidget',
  tags: ['a11y'],
} satisfies Meta
```

Run the audit locally with the visual harness. It runs in Docker, like CI:

```bash
# from packages/app
yarn test:visual -g "a11y:"
```

Unit tests (`yarn test`) also check the theme: every preset colour against the text colour drawn on it (4.5:1), the form error colour and the focus ring against the app background and cards (`tests/configs/app.test.ts`), and the contrast maths itself (`tests/lib/color.test.ts`).

## Colour and contrast

- **Text on a colour.** SApp sets `--s-color-<name>--text` for each preset colour, and components pick text for a custom `color` the same way: the light or the dark theme text colour, whichever has the higher [WCAG contrast ratio](https://www.w3.org/TR/WCAG22/#dfn-contrast-ratio) with the background. If you pass `colorThreshold`, the old YIQ brightness rule is used instead (0-100; `colorThreshold` from `@khsura/sui` holds the former default, 55).
- **Default theme.** `success` is `#2e7d32` and the light theme's `secondary` is `#cc4125`, so white text on them reaches 4.5:1. The old `#4caf50` green reached 2.73:1. If you override a preset colour, check that it reaches 4.5:1 with the light or the dark theme text colour (any contrast checker works; the library uses `getContrastRatio` from `lib/color.ts` internally).
- **Preset colours as text.** `color` on text-like uses (`s_textColor__<name>`, text buttons, outlined chips) reads `--s-color-<name>--readable`: the preset mixed toward the theme text colour just enough to reach 4.5:1 on the app background and on cards. Primary text on a dark card, for example, is lightened.
- **App colours.** `textError` is the colour of form error messages (`#df0101` light, `#ff8a80` dark). `focusRing` is the keyboard focus ring (`#134ff3` light, `#8ab4f8` dark).

## Names and descriptions

- **Icon-only buttons need a name.** An `SButton variant="icon"` (or `icon`) that holds only an `SIcon` has no text, so pass `aria-label`: `<SButton variant="icon" aria-label="Close"><SIcon icon="mdi-close" /></SButton>`. The SUI MCP validator warns about a missing one. SUI's own icon buttons have English defaults that you can override: the date picker arrows (`prevAriaLabel`, `nextAriaLabel`), the slide group arrows (`prevAriaLabel`, `nextAriaLabel`), the autocomplete clear button (`clearAriaLabel`) and the table pagination.
- **Form fields.** SInput, STextarea, SSelect, SAutocomplete and SDatePickerInput tie their `label` to the control, and generate an `id` when you do not pass one. With `hideDetails` the label is hidden, so it becomes the control's `aria-label`. A field without a visible label takes `ariaLabel`.
- **Errors.** While a rule fails, the control (or the SRadioGroup) gets `aria-invalid="true"` and `aria-describedby` pointing at the error message, and the message is a polite live region.
- **Progress.** SProgressCircular and SProgressLinear are named `Loading` by default. Pass `aria-label` to say what is loading.

## Keyboard checklist

Run this in the Storybook (light and dark theme) after you change one of these components. Use only the keyboard. Every focused element must show a visible focus ring: the 2px `focusRing` outline that buttons, toggle buttons, tabs, the select field, checkboxes, radios, switches, editable stepper steps and scrolling regions draw under `:focus-visible`.

| Component | Tab | Keys |
| --- | --- | --- |
| SButton | One Tab stop; disabled buttons are skipped | Enter and Space activate |
| SSelect | The field is one Tab stop (`role="combobox"`) | Enter, Space, Down or Up opens the list. Down / Up move the highlighted option, Home / End jump to the first / last. Enter or Space picks it. Esc closes without picking (an SDialog around it stays open). Tab closes the list and moves on |
| SAutocomplete | The input is one Tab stop (`role="combobox"`) | Typing filters. Down / Up open the list and move the highlighted option. Enter picks it (or adds the typed text when nothing is highlighted). Esc closes the list. Backspace in an empty input removes the last chip |
| STabs | One Tab stop: the selected tab (`role="tab"`) | Left / Right move to and select the previous / next tab, wrapping around. Home / End select the first / last |
| SRadioGroup | One Tab stop: the selected radio (or the first, when none is) | Up / Down / Left / Right move to and select the next radio (native radio behaviour, one `name` per group) |
| SToggleButtonGroup | Each toggle button is a Tab stop (`aria-pressed`) | Enter and Space toggle |
| SSlideGroup | The arrow buttons and each item are Tab stops | Enter and Space activate the arrows and items |
| SStepper | Each editable step is a Tab stop (`role="button"`); the current step has `aria-current="step"` | Enter and Space go to the step |
| SDatePickerInput | The input is one Tab stop | Type the date in the shown format and press Enter. Esc closes the calendar |
| SDatePicker | Each day, the month/year switch and the arrows are Tab stops; days outside `min`/`max` are disabled | Enter and Space pick a day. Each day button is named with the full date, today has `aria-current="date"` |
| SMenu, SDialog | See the overlay docs | Esc closes and focus returns to the activator; SDialog keeps Tab inside |
| STable, scrolling SCardText, SNavigationDrawer | A region that scrolls becomes a Tab stop | Arrow keys scroll it |

Also check that the Tab order follows the visual order, and that nothing gets focus while it is hidden.
